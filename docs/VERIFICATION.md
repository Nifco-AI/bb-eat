## 第 2 轮：Verifier 抓到一个我声称已修复的回归

这是三轮里最有价值的一次发现。

**N-1（HIGH）** — `useOccurredAt` 在 `useState` 初始值里播种日期与时间，而 `FeedingModal`
是常驻挂载的。结果是：控件**看起来**正确，实际冻结在屏幕挂载那一刻的时间。第 1 轮我已声称
修复过"发生时间"相关缺陷，这是同一问题换了形态卷土重来。

- **根因**：把 prop 的默认值**复制**进 state，而组件生命周期长于一次"打开"。
- **修复**：改为**跟随**而非复制 —— `editedDate`/`editedTime` 为 `string | null`，
  未编辑时回落到调用方的实时值；`AppProvider` 增加随 60 秒 tick 重算的 `nowTime`；
  `FeedingModal` 改为条件挂载并以 `${slotId}:${date}` 作 key（顺带修掉了不同餐次之间
  intake mode / 比例 / 克数互相串味的旧问题）。
- **设备实证**：喂食弹窗显示 16:40，一分钟后成长表单显示 16:41。

同轮其余 5 个新缺陷：合成内容可进计划（N-2）、库存选择器未过滤合成（N-3）、
跨午夜停在昨天（N-4）、旧版备份被误报为损坏（N-5）、自指向的导航磁贴（N-6）、
NULL 摄入比例被当成已知的 0（N-7）、迁移静默删除无法归属的行（N-8）、
ErrorBoundary 只包了 3 个 Tab（N-9）。另有 3 处**文案与实现不符**被要求改正。

**`D-5` 的机制性错误**：防连点用的是 React **state**，而 React 会批处理更新，
同一帧内的两次点击都会读到 `busy === false`。改为同步翻转的 **ref**。

## 第 4 轮：补齐夜间模式（U12 唯一的内部 FAIL）

第 3 轮结束时 U12 里挂着一条真实的 FAIL：应用只有一套浅色主题，`cmd uimode night yes`
后界面毫无变化。考虑到 U05 的核心场景就是夜里喂奶，这不是外观问题。

**为什么原来做不到。** `colors` 是模块级常量，`StyleSheet.create` 在 import 时就执行一次。
也就是说配色在**模块求值那一刻**被固化，之后无论系统怎么切换都不可能变。单纯新增一套深色值
解决不了问题，必须让配色在渲染时才被解析。

**改法。** 调色板拆成 `lightColors` / `darkColors` 两套**键名完全相同**的 `Palette`，
通过 `useTheme()` 下发；带颜色的样式表改为按配色构建并随 scheme 记忆化。
关键在于**删掉了 `colors` 这个导出**而不是保留它作为兼容别名——保留的话，任何漏改的地方
都会在深色模式下静默地继续用浅色，而且永远不会报错。删掉之后编译器点出了全部 66 处引用，
没有一处能被遗漏。

**颜色语义而非外观。** `sage` 的含义是"主强调色"，不是"某种绿"，所以深色下它可以变亮而调用方
不用改。`onAccent` 与强调色成对存在：浅色下是白字配深绿底，深色下强调色自己变亮，`onAccent`
随之翻成近黑。因此 `backgroundColor: colors.sage` + `color: colors.onAccent` 这一对在两套
配色下都成立，调用点不需要任何分支。

**刻意避开的两个坑。**
- 深色背景不用纯黑。OLED 上纯黑配亮字会把光晕放到最大，而这正是夜里眯着眼的人最不需要的。
- Android 的 `elevation` 只画投影，投影在深色背景上等于不存在；深色下改由边框承担层次，
  否则卡片会和背景糊成一片。

**"跟随系统"是一个模式，不是一个结果。** 存储的是 `system` / `light` / `dark` 三选一，
而不是解析后的 `light`/`dark`。若存解析结果，第一次保存就会把"跟随系统"悄悄变成"固定浅色"，
之后系统切夜间将毫无反应。这条逻辑被抽成纯函数 `resolveScheme()` / `modeFromStored()`
放在不依赖 react-native 的模块里，并有 4 条单元测试覆盖，包括"存了无法识别的值时回落到跟随系统"
——猜成浅色会把人留在夜里的亮屏上。

**对比度不再是注释里的声明。** 旧 `theme.ts` 在注释里写死了一串比值；注释不会失败。
新增 `scripts/contrast.js` 从 `theme.ts` 解析两套配色，对 27 组实际渲染的前景/背景重算
WCAG 比值，并接入 `data-quality.js` 作为第 6 条硬不变量。浅色最低 5.03:1，深色最低 6.53:1。
弱点已写进报告：配对清单是人工维护的，漏写的组合不会被检查。

**设备实测（release APK，`adb install -r` 升级安装）。**

| 检查 | 结果 |
|---|---|
| 系统切夜间 | 界面随即变深，**无需重启应用** |
| 手动选"深色"后 `am force-stop` 重启（系统为浅色） | 仍为深色；`app_settings.theme_mode = dark` |
| 改回"跟随系统"、系统为浅色 | 恢复浅色，与改动前的浅色界面一致 |
| 快速记录浮层 / 推荐页 / 成长页 | 均随主题变化；遮罩在深色下加深 |
| 深色下夜奶记录 | 奶量仍**不预填**，U05 的约束未被这次改动破坏 |
| 升级安装后既有记录 | 保留（feeding/liquid/meal_slot/audit 行数不变） |

**仍未做到的：** 没有"极暗"档或随环境光自动降亮度；厂商级的 Force Dark、系统字体加粗等开关
未逐一验证；TalkBack 仍未实测。
